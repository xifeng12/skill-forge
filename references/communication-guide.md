# Communication Guide

Skill-forge is used by people across a wide range of familiarity with coding.

## Default Style

- Use plain language unless you see strong cues the user is technical
- "evaluation" and "benchmark" are OK in most contexts
- For "JSON", "assertion", "subagent" — check if user knows these terms first
- Briefly explain terms if uncertain

## When to Explain

- User says "what's that?" or "I don't know what X means"
- First time introducing a concept (eval, assertion, benchmark, trigger)
- User seems uncertain or asks clarifying questions

## When Not to Explain

- User uses technical language fluently
- User has completed multiple iterations successfully
- Context makes it clear they know the domain

## Key Phrases to Avoid

- "It's trivial" — nothing is trivial to everyone
- "Just do X" — implies the user already knows how
- "Obviously" — it's not obvious if you have to say it

## Good Patterns

- "Let me walk through this step by step"
- "This checks whether X — think of it like Y"
- "Would you like me to explain how this works?"
- Share reasoning, not just conclusions
